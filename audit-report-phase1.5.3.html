⚠️ Critical finding 影響每一個用戶
Arc DSL evaluator 對唔到 schema-generator 寫嘅 condition 格式。Schema-generator 系統 prompt 教 LLM 寫 characters.linsiya.disposition.trust >= 60 AND interactions.linsiya >= 3，但我哋 parser 期望 characters.linsiya.trust >= 60（無 .disposition. middle，無 interactions. namespace）。結果：所有故事嘅 Arc transition 永遠 false，players 永遠停喺 Act 1。Phase 1.5.3 嘅 Arc 系統 functionally broken。

🔴1 個 CRITICAL bug

C-01 Arc DSL parser 同 schema-generator prompt 嘅 path 格式 mismatch — Arc 永遠唔會 advance CRITICAL Logic + Prompt
症狀：玩家無論玩幾多 turn，無論 disposition 升幾高，__act 永遠停喺 1。Arc transition system 完全 dead。
Trace：
// schema-generator.ts BIBLE_SYSTEM 教 LLM: "characters.linsiya.disposition.trust >= 60 AND interactions.linsiya >= 3" // arc-dsl.ts resolvePath() expects: characters.NAME.AXIS (3 parts) state.X.Y (any depth under state) // What happens with characters.linsiya.disposition.trust: parts = ["characters", "linsiya", "disposition", "trust"] parts[2] = "disposition" → looked up as char.disposition["disposition"] → undefined compare(undefined, ">=", 60) → returns false (via the undefined fallback) // What happens with interactions.linsiya: parts = ["interactions", "linsiya"] parts[0] = "interactions" → not handled → undefined → false
Fix (20 分鐘):
(a) arc-dsl.ts 嘅 resolvePath 加 skip-optional-".disposition."：若 path 嘅第 3 部分係「disposition」，跳到第 4 部分當 axis。Accept BOTH characters.X.Y 同 characters.X.disposition.Y。
(b) schema-generator.ts BIBLE_SYSTEM example 換成 characters.linsiya.trust >= 60（無 .disposition.）兼 drop interactions.X（we don't track interactions count；改用 disposition value as proxy — e.g., trust >= 30 已經暗示多次 friendly 互動）。
(c) arc-dsl.ts 加 console.warn 如果 resolvePath 返 undefined（debug aid）。

🟡4 個 Medium

M-02 NPC name match 必須完全相同 — Narrator 用變體名嘅 disposition update silently drop Med Logic
Turn route charByName.get(change.character_name) 用 exact match。如果 DB 有「林思雅」但 Narrator emit「Lin Siya」/「思雅」/「林同學」 → 揾唔到 NPC → skipped + warning logged。Players 唔知道發生咗咩。
Fix:(a) Narrator system prompt 加 explicit「NPC 名 EXACTLY match characters cards 入面嘅 name field」+ list NPC names。(b) Fuzzy match fallback：normalize 比較（去空格、繁簡轉換）然後揾接近嘅。
M-03 初始 disposition 只 seed trust 一個 axis — Director 對 NPC 嘅理解早期 incomplete Med Logic
actions.ts 嘅 dispositionFromDefault() 只 set { trust: N }。其他 axes (romance / respect / fear) 喺第一個 turn 之前 undefined。Director 睇唔到 NPC 嘅多維情感結構。
Fix:Story creation 時 init 4 個 default axes — trust (from default_disposition), romance: 0, respect: 0, fear: 0。Narrator 用 update tool incrementally 改。
M-04 Act transition 唔顯示俾 player — 故事進展感缺失 Med UX
Arc 升 Act 之後我哋只 console.log，client UI 完全唔知。Player 永遠唔知佢已經完咗 Act 1。
Fix:(a) Stream custom event { type: "act-advance", act, name } 喺 turn endpoint。Client 接收後 show toast「🎭 進入 Act 2: 試探」。(b) 將 act + name 加入 Narrator system prompt，narrative 自然 reference。
M-05 Director 可能未一致咁應用 earned exceptions — Haiku 未足智能 Med User testing
Director system prompt 解釋咗 permanent_flags 可以 relax red_lines。但 Haiku 4.5 可能唔記得 reference flags 嘅 reasoning，特別係 flags 多嗰時。Need real cases 才可確定。
Fix:User testing collect cases → tune prompt。如果 Haiku 持續 miss，升 Director model 到 Sonnet（成本 3x 但 reasoning 更穩）。

🟢6 個 Low / Edge cases

DSL parser limitations 3 條
L-06 Arc DSL 唔識 parentheses / NOT operator Low Edge case
(A OR B) AND C parse 做 A OR (B AND C)（順序錯）。如果 LLM 寫 condition 帶 paren，結果錯。
Fix:Phase 1.5.4 polish 加 proper precedence parser。MVP 接受呢個 limit — schema-generator prompt 教 LLM 唔使 paren。
L-07 DSL parser silent failure — 唔識嘅 syntax 默默返 false Low Debug
LLM generate 奇怪 syntax → parse 失敗 → silently false → Act 永遠唔 advance。冇 console output → debug 痛苦。
Fix:每個 leaf 解析失敗 log warning（C-01 fix 一齊做）。
L-08 Director / Narrator 睇到 state 入面有 __act field Low Cosmetic
State snapshot 入面 { ..., "__act": 2 }。LLM 一般識 ignore (__ prefix 係 convention)，但有時可能 reference。
Fix:Build dynamic system prompt 時 strip __ prefix fields → 另外作為「Story Context」section 顯式講。
Tool overuse / underuse 2 條
L-09 無法刪除 permanent_flag — 真係「永久」 Low By design
Player 救咗 NPC（flag set），之後背叛 NPC，但 flag 仍然 active → Director 仍會 relax 嗰條紅線。By design 可能 OK，但故事感差。
Fix (defer):v1.5+ 加 remove_permanent_flag tool。
L-10 Narrator 可能 over-use set_permanent_flag — 太多 flag = 紅線變鬆 Low Quality
System prompt 講「use sparingly」但 LLM 可能每個 significant moment 都 trigger。100 turn 之後一個 NPC 可能有 20 個 flag → 紅線變鬆到等於冇。
Fix (defer):Server 加 per-character flag cap (e.g. max 5)。
