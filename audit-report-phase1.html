🛠️ 4 個今次修咗嘅 issue

M1
Story creation 冇 transaction — partial failure 留 orphan rows
Med Fixed src/app/[locale]/stories/new/actions.ts
createStoryFromPrompt 做 4 個 INSERT (story / characters / playthrough / character_states / opening turn)。Supabase JS client 冇 native transaction。如果 step 2/3/4 失敗 → step 1 嘅 story 留底，無 character 嘅 orphan 故事永遠出現喺用戶 library。
Fix: 加 cleanup(storyId) helper — 失敗時刪除 story (CASCADE FK 自動清埋 characters / playthroughs / states / turns)。Best-effort manual transaction。Phase 2 可以考慮 RPC function 做 proper SQL transaction。
M2
validateValue 太嚴格 — LLM string-number 失敗 silent
Med Fixed src/schemas/state-delta.ts
LLM 偶爾會 output "50" (string) 代替 50 (number)，雖然 Vercel AI SDK 嘅 tool input 應該已 Zod parse，但 inc 嘅 by 值同直接 set 嘅 value 仍可能係 string。嚴格 typeof === "number" 直接 throw → state delta 失敗 → state 唔變。
Fix: 新 coerceNumber(v) helper 接受 number 或可轉 number 嘅 string。validateValue 同 inc 都用佢。LLM 出 string 都 graceful handle。
M3
state_schema 容許 duplicate field keys
Med Fixed src/schemas/state-schema.ts
Zod array of FieldSchema 冇 key uniqueness check。LLM 可能 generate 兩個 field 同名 (e.g. 兩個叫 hp)。renderer Map 用 key 做 index → last wins silently，前者完全消失。
Fix: StateSchemaShape.refine(...) 確保 keys 全 unique。LLM 出 duplicate → generation 失敗 → 顯示錯誤俾用戶（佢可以重試）。
M4
applyDelta 一個 op fail 就 throw 整個 delta — 太 aggressive
Low Fixed src/schemas/state-delta.ts + turn route
原本 LLM 出咗一個壞 op (e.g. inc on inventory_list)，整個 delta throw exception → onFinish catch → state 完全唔變。其他 valid ops（e.g. set on 好感度）都被一齊扔走，玩家見到敘事但狀態唔變，confusing。
Fix: applyDelta 改成 return { state, applied, skipped }。Per-op try/catch — invalid ops skip + reason 記入 log，valid ops 仍然 apply。Turn route 跑完 log warning 但保留 valid changes。
