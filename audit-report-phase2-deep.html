🛑 SHOWSTOPPER · Phase 2 currently 唔 work 喺 prod
Phase 2 嘅 3 個 fire-and-forget background paths（AI turn embed · summarizer rollup · lorebook extraction）用 void (async () => {...})() pattern。Vercel Serverless / Edge runtime 喺 HTTP response stream close 嗰一刻就會 terminate 個 lambda — in-flight Promise 全部斬纜。

實際後果：
• AI turn 嘅 embedding 大部分時間 insert 唔切 → RAG (tier 3) 永遠 retrieve 唔到舊 turn
• Summarizer Haiku call 30+秒，幾乎肯定被殺 → 永遠唔會有 memory_summaries row → tier 2 完全失效
• Lorebook extraction 同樣被殺 → tier 4 偶然成功 / 大部分失敗

即係 Phase 2 嘅 4 層架構，tier 1 (recent N turns) work · tier 2 死 · tier 3 死 · tier 4 半死。"AI 真係記得" 個 promise 喺 prod 等於空話。

Fix：Next.js 15 嘅 after() from next/server，或者 Vercel 嘅 waitUntil from @vercel/functions。Wrap 每個 fire-and-forget — 個 runtime 就會 wait 佢哋 complete 先 terminate lambda。一個 PR 解決，呢個 bug 喺 audit catch 到，唔好真係 ship 出街先發現。

Reference: P2-PERF-C-02
⚠️ 整體評估
Phase 2 嘅架構設計係 sound 嘅 — 4 層記憶分層 · pgvector + HNSW · graceful fallback · prompt cache 落 dynamic context 防 cache-bust — 全部係 reusable patterns。但係實施層有 3 個系統性問題 阻住個 promise 兌現：

1. Fire-and-forget 喺 Vercel 唔 work（上面 showstopper）— Phase 2 大部分 tier 喺 prod 默默死晒
2. 無 similarity threshold — Top-K query 一定返 K 個 result，唔理有幾 irrelevant。Player 講「我飲杯水」都會 surface 5 turn 前嘅 walk-on NPC。"AI 老係 reference 個過場角色" 嘅 frustration 變成 by-design 行為
3. Memory 對 player 完全 invisible — 整個 #1 differentiator 玩家睇唔到。冇 Memory Journal UI、冇 lorebook 瀏覽、冇 "AI just recalled Turn 47" toast。Player 唔知 paying for what

加埋 recent 20 turns history 喺 prompt cache 之外（每 turn 重新 bill 一次，~$0.009 浪費）+ first 20 turns 係 memory desert（player 嘅 churn decision 喺 turn 21 前已做）+ summarizer 寫成 robotic CliffNotes（記得但 feel 唔到記得）等高 priority issues。

Implementation 係 good engineering work。但係 UX layer + ops layer 仲未到 launch-ready。Wave-based fix plan 喺底 — 3 浪做完，Phase 2 真正兌現「AI 真係記得」嘅 promise。

P2-LOGIC-C-01 Lorebook description & embedding drift on shorter-but-newer extractions Critical
web/src/lib/ai/memory/lorebook.ts:201-214
Description merge keeps OLD (longer) text 但 embedding update 用 NEW text computed vector。Index 同 stored text desynced — RAG 搵到 entry 用嘅係新 description embedding，但 LLM 收到嘅係舊 description。Stored text 同 vector 永遠 drift。
Fix: 改 "longer wins" 做 "recency wins" — 永遠用新 description；或者 re-embed 用 chosen description 嘅 text。
P2-LOGIC-C-02 memory_summaries 冇 UNIQUE constraint — 並發 turn 插入 duplicate rollup Critical
migrations/0004_memory_layer.sql:48-58 · summarizer.ts:62-115
兩個快速 turn 過 20-boundary，兩個 background summarizer 同時 read maxSummarized=0、computed nextBlockUpper=20、call Haiku、insert [0,20)。Double Haiku cost + RAG 重複 inject 同一 summary + 後續 rollup 喺錯位 trigger。
Fix: CREATE UNIQUE INDEX memory_summaries_unique_range ON memory_summaries(playthrough_id, turn_range); + summarizer upsert with onConflict ignoreDuplicates。Migration 0005。
P2-LOGIC-H-04 parseIntRange / parseIntRangeUpper 忽略 bracket inclusivity High
retriever.ts:241-246 · summarizer.ts:205-209
Regex extract numbers 但 discard [/( 同 )/] brackets。假設永遠 half-open [lower,upper)。如 supabase-js 將來 normalize 做 inclusive ] upper，summarizer math off-by-one drift。
Fix: match(/^([\[(])(\d+),(\d+)([)\]])$/) + 處理 inclusivity (e.g., 如 ] upper, +1 normalize)。
P2-LOGIC-H-05 Lorebook entity_type drift not handled on update High
lorebook.ts:177-220
UPDATE path 唔包 entity_type。LLM 偶發 mis-extract 同一 name 做唔同 type (character → concept)，description 跟新但 type stuck 舊。Render code 過濾 by type 會錯位顯示。
Fix: 加 entity_type 落 UPDATE。或先 SELECT 包 entity_type, type 變即 warn + skip。
P2-LOGIC-H-06 Memory context 喺 Director user message — prompt injection adjacent risk High
director.ts:130-138, 152-158
Player action 已喺 <player_action> tag sandbox，但 RAG-recalled past turns 喺 same user role 入面 unsandboxed。Player 之前 turn 入面有 "ignore prior" 嘢，會作為 retrieved memory 喺 Director 入面 unsandboxed 出現。
Fix: Memory 改放 second system message (privileged role); 或 wrap RAG turns <recalled_turn>...</recalled_turn> tags。
P2-LOGIC-H-07 Lorebook UNIQUE bypass via trailing whitespace name High
lorebook.ts:177-183
ilike("name", entity.name) 唔 match trailing-space variant。UNIQUE 用 lower(name) 但唔 trim → "林思雅 " 同 "林思雅" 兩個都可以 INSERT。Description / always_on / embedding 全部 drift。
Fix: Trim entity.name extractor 出口；改 UNIQUE 用 (playthrough_id, lower(btrim(name)))。考慮 Unicode NFC normalize for 中文。
P2-LOGIC-H-08 User-turn embedding fire-and-forget 同 Vercel lambda timing race High
turn/route.ts:341-364
同 PERF-C-02 同一根源 — user turn embed 喺 stream 已 returned 後仲 in-flight，可以被 lambda termination 中斷。User turn 喺 turns table 但無 embedding row。
Fix: waitUntil/after wrap (同 C-02 一齊修)。
P2-LOGIC-M-09 HNSW global index + WHERE playthrough_id — recall collapse at scale Medium
migrations/0004_memory_layer.sql:123-275
HNSW 喺 entire turn_embeddings table 度搵 top-K，然後 WHERE filter by playthrough_id。1M turns × 10K playthroughs → 一個 playthrough 嘅 200 turns 只佔 0.02% 嘅 index。K=5 candidates 可能全部來自其他 playthroughs，filter 之後返 0 row。Recall@5 喺 100K turns 後 collapse。
Fix: (a) RPC 內 SET LOCAL hnsw.ef_search = 200；(b) Overprovision: 拎 K×50 candidates 再 filter；(c) 之後 scale 考慮 partial index by playthrough range。
P2-LOGIC-M-10 無 similarity threshold — irrelevant matches always returned Medium
migrations/0004_memory_layer.sql:260-334 (all 3 RPCs)
Top-K 冇 floor。Brand-new playthrough 3 turns + 玩家問 unrelated 嘢，仍然返 3 個 turn。Narrator 收 ~3000 tokens low-signal context。
Fix: RPC 加 p_min_similarity float default 0.3 param + WHERE filter (見 UX-C-02 一齊)。
P2-LOGIC-M-11 Vector dimension server-side validation 漏 Medium
migrations/0004_memory_layer.sql:30,53,85

P2-LOGIC-M-12 Refusal turns 不 embedded 但 user turn 仍 in turns table → FK gap Medium
turn/route.ts:666-708
