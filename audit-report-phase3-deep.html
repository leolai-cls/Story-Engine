🛑 SHOWSTOPPER · 任何 user 可以 drain 或 mint 任何人嘅 credit balance
P3-SEC-C-01：apply_credit_charge RPC 係 SECURITY DEFINER（bypass RLS）並 GRANT 比 authenticated role，但係 function 入面冇 verify auth.uid() = p_user_id。任何 logged-in user 可以打：

supabase.rpc('apply_credit_charge', { p_user_id: '<victim-uuid>', p_delta: -999999, p_reason: 'turn_charge' })

→ drain 受害者 balance；或者：

supabase.rpc('apply_credit_charge', { p_user_id: '<self-uuid>', p_delta: +999999, p_reason: 'topup' })

→ mint 無限免費 credits。credit_ledger 嘅 SELECT policy 只 filter own row，所以受害者見唔到非法 entry，淨係見 balance 變咗。

影響：違反 CLAUDE.md hard rule #4 「Credits 計算邏輯要絕對啱」。一個 attacker 可以 wipe 晒所有 paid customer 嘅 balance OR 自己 mint 無限 credit。Phase 4 Stripe 一上線即時 bypass。呢個 bug 喺 prod 真係 active 嘅（migration 已 apply）— 即係而家就可以被人 exploit。

必須即時 fix：喺 RPC 內加 if auth.uid() <> p_user_id and current_setting('request.jwt.claims', true)::jsonb->>'role' <> 'service_role' then raise exception 'forbidden'。
