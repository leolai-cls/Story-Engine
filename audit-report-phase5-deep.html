🛑 SHOWSTOPPER #1 — CSAM / sexual-minor pre-filter 完全冇
P5-SEC-C-01：Migration 0009 加咗 'csam' 同 'sexual_minor' 入 moderation_flags.reason enum — 暗示呢啲 vector 存在 — 但係故事創作冇任何 pre-filter。Prompt / opening narrative / story bible / red lines 全部冇 scan。

CLAUDE.md hard rule #6：「CSAM / 違法內容 pre-filter — 法律底線，唔可以 bypass」。違反咗。Vercel + Supabase + Stripe + Anthropic + OpenAI ToS 全部都禁，就算暫時 host 都唔可以。

Repro：登入 → 創作 explicit CSAM 主題故事 → 即時 published → FTS 入晒 → 玩到就 trending。

Fix：createStoryFromPrompt + upsertComment + rateStory 加 OpenAI Moderation API call (free per CLAUDE.md)。Block save on categories.sexual/minors or hate over threshold。Phase 5 launch 之前必須有。
🛑 SHOWSTOPPER #2 — play_count 可以無限灌水
P5-RACE-C-01：bump_story_play_count trigger 有 INSERT 路徑但冇 DELETE 路徑。RLS playthroughs_own_delete 容許用戶刪除自己嘅 playthrough。冇 rate limit on forkStoryToPlaythrough。

攻擊路徑：fork → delete → fork → delete 循環。每 fork +1 play_count，delete 唔減。Curl loop 數秒內可以將任何對手嘅 story play_count inflate 1000x。

影響：Trending 公式直接讀 ln(play_count + 1) × decay × quality → leaderboard 變 adversarial。Launch day 第一個 troll 就玩爆。

Fix：(a) 加 AFTER DELETE trigger decrement when deleter != owner。(b) forkStoryToPlaythrough rate limit (e.g., 1 fork / user / story / hour)。(c) Trending 改用 COUNT(DISTINCT user_id) 而唔係 raw row count — fork spam 唔可以 inflate distinct count。
🛑 SHOWSTOPPER #3 — Owner 可以 5★ bomb 自己故事
P5-SEC-C-02：story_ratings_own_insert RLS policy 要求 auth.uid() = user_id AND story.visibility = 'public' — 但係冇 require user_id != stories.owner_id。Action layer 都唔 check。

結果：Owner publish 故事 → 自己 rate 5★ + 寫好評 → rating_avg = 5.0, rating_count = 1。配合 #2 嘅 play_count 灌水 → 單人 takeover trending。Launch day attack vector。

Fix：RLS policy 加 AND NOT EXISTS (SELECT 1 FROM stories WHERE id = story_id AND owner_id = auth.uid())。Action mirror 同個 check 做友好 error。
🛑 SHOWSTOPPER #4 — Comment UPDATE policy 開晒，可以 bait-and-switch
P5-SEC-H-02（其實係 critical 嚴重程度，列 high 因為要 multi-step）：story_comments_own_update 用 using (auth.uid()=user_id) with check (auth.uid()=user_id) — 冇限制邊個 column 可以改。

攻擊：用戶可以(1) un-delete 自己 comment (deleted=true→false)，(2) 悄悄編輯 body 冇 audit trail，(3) re-parent 自己 comment 指向另一個 story 嘅 parent，(4) 改 story_id 將 comment 搬去其他 story。

Bait-and-switch：友善留言 → 累積 likes → 改 body 做侮辱性內容 → 但仍喺原 thread。Cross-story parent_id 破壞 thread invariant。

Fix：Trigger 喺 UPDATE 時 revert 所有 column changes except deleted（false→true only）。或者 split 做 separate "edit body" action with explicit edited_at column。
