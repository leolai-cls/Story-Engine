CRITCRIT-03Migration 0033 backfill loop · ledger balance_after 用 stale snapshot

supabase/migrations/0033_fix_signup_grant_50_to_1000.sql:64-78

Backfill loop 結構：(1) FOR v_user IN SELECT id, credit_balance FROM profiles WHERE ... (snapshot)，(2) UPDATE profiles SET credit_balance = credit_balance + 950 WHERE id = v_user.id，(3) INSERT credit_ledger ... balance_after = v_user.credit_balance + 950。第 3 步用嘅 v_user.credit_balance 係 snapshot 時嘅值，唔係 UPDATE 之後嘅實際值。如果 user 喺 snapshot 同 UPDATE 之間 charge 過（race），ledger 嘅 balance_after ≠ 實際 balance。

影響： Ledger drift = CLAUDE.md hard rule #4 違反（「off-by-one = trust collapse」）。Migration 文件夾入面 raw UPDATE 冇 row lock · 冇透過 apply_credit_charge RPC。即使現在「零 users」，如果 backfill 喺有真實流量嘅 staging / future re-run 上面跑，ledger 表會搞亂。

Fix 將 backfill 改用 apply_credit_charge(v_user.id, 950, 'admin_adjust', null, key, metadata) · 或者改 loop 為 UPDATE ... RETURNING credit_balance INTO v_new_balance 然後用 RETURNING 值做 balance_after。記得加 FOR UPDATE row lock。
