#1
Settings 卡 link 去唔存在嘅 sub-pages → 404
High Fixed src/app/[locale]/settings/page.tsx
原本 <Link href="/settings/profile" /> 等 3 條 sub-route，但 /settings/profile / /settings/billing / /settings/models 都唔存在，click 落去 404。仲用咗 href as never TypeScript hack 隱藏 type error。
Fix: 將 Card 改成 non-clickable (移走 Link wrapper)，加 "Coming soon" badge 顯示狀態。用戶睇到清晰預告，唔會撞 404。
#2
5 個檔案有 hardcoded 繁中字串 → 切去 /en 仍見繁中
High Fixed library / profile / settings / footer / pricing pages
Library、Profile、Settings 嘅標題同 body 全部 hardcoded 繁中。Footer 「中文圈 first」、Pricing 嘅 USD 提示都係。Switch 去 /en 應該顯示英文，但呢啲位永遠係繁中 — 違反 i18n 設計。
Fix: 加 pages.library / pages.profile / pages.settings / footer.tagline / pricing.usdNotice keys 入 3 個 messages JSON (繁中/簡中/英)，重寫所有 component 用 getTranslations。
#3
Site Header「Pricing」link 純英文唔 translate
Med Fixed src/components/site-header.tsx
Header 嘅 Library link 用 t('library') 翻譯，但 Pricing 寫死 "Pricing"。
Fix: 加 nav.pricing key (繁中：訂價、簡中：订价、EN：Pricing)，header 改用 t('pricing')。
#4
globals.css --font-sans tautology → 繁中字體 fallback 去 Geist (拉丁字體)
Med Fixed src/app/globals.css
原本 --font-sans: var(--font-sans); 係 self-reference (循環)，最後 browser fallback 去 system default。Geist 字體只支援拉丁字符，繁中字體會 fallback 到 user 系統嘅字體 — 可能係差嘅字體 (e.g. MingLiU)。
Fix: 改成 --font-sans: var(--font-noto-sans-tc), var(--font-geist-sans), system-ui, "PingFang TC", "Microsoft JhengHei", "Heiti TC", sans-serif; — Noto Sans TC 優先 (我哋 load 嘅)，fallback 去 system 字體，最後 sans-serif。繁中字體永遠靚。
#5
profile auto-create trigger 只 read name field → Google OAuth 用戶 display_name = email
Med Fixed supabase/migrations/0001_initial.sql
原本 coalesce(raw_user_meta_data->>'name', email)。但 Google OAuth 將 user name 放喺 full_name 或 given_name，GitHub 用 user_name。Google 登入嘅用戶會見到自己 display_name 係 email，UX 差。
Fix: coalesce chain 擴展到 name → full_name → user_name → email。Avatar 都加 picture field (Google OAuth 用呢個 field 唔係 avatar_url)。同時加 security definer set search_path 加固 set_updated_at() function (best practice)。
