0點解要重新諗

舊 agent mode 唔係冇做 — 係佢嘅「開關掣」喺 light-core 拆咗

舊 agent mode（NPC 內心戲）本身整好咗：每個活躍 NPC 有自己一個 AI 喺度諗「我記得啲咩 → 我估佢哋會點 → 所以我想點」，再餵畀講故事嗰個 AI。機器本身冇問題。

但係邊個 NPC「而家喺場、要諗嘢」，舊設計係靠 GM（嗰個每回合仲裁嘅 AI）話畀佢知。我哋 light-core 拆咗 GM → 個開關掣冇咗訊號源 → agent mode 變成「撳極都唔郁」→ 跟手清理咗段死碼。

所以核心問題只有一個
冇咗 GM，系統點知「邊個 NPC 而家活躍、要諗嘢」、幾時要擲骰、幾時開任務？ 解決咗呢個，其餘嘅嘢大半可以由 git 撈返舊碼接返。

1深模式包含咩

你揀咗「完整深模式」= 三大部件一齊（之前傾嘅 a + c 全套）
部件 A

NPC 內心戲

每個在場 NPC 有自己嘅 AI 諗私密心理：記憶、估你同其他人會點、自己嘅動機。佢哋唔改劇情，只係令講故事嗰個 AI 寫得出「呢個角色真係有自己諗法」。

阿明表面笑住應酬你，但佢心入面「上次你出賣咗我 → 今次唔會再信」→ 故事就會寫到佢笑得有距離、答嘢留一手。
部件 C1

擲骰／機制

每個故事 AI 喺創作時生成自己一套機制（D&D 擲 d20、戀愛冇骰、寵物捕捉、推理對質⋯）。講故事嗰個 AI 自己識「呢下要擲骰」就叫個系統擲，再照結果寫落去。

你話「我跳過個峽谷」→ AI 自己叫擲敏捷骰 → 擲到 6 → 故事寫你險險踩空、抓住藤條吊喺半空。
部件 C2

任務系統

故事有可追蹤嘅目標／章節線：開任務、推進、完成。畀玩家有「我喺度追緊一條主線」嘅感覺，唔係散修修。

「搵返失蹤嘅妹妹」會喺一個唔搶戲嘅地方顯示進度，唔係彈一格數字出嚟。

⚠️ 老實講：C1 同 C2 喺現狀其實係新嘢（舊嘅擲骰只係 GM 預判，已廢；機制生成從來未起）。所以三件嘢入面，A 最快（撈返舊碼接新掣），C1 中等，C2 最大（要由零設計任務嘅資料結構）。

!最關鍵嘅一個決定

冇咗 GM，「邊個 NPC 活躍」靠咩訊號？呢個揀錯，成個深模式都會怪

我哋已經有幾個現成、唔使 GM 嘅訊號可以用：

方法點 work好處缺點
認名（現有）掃描啱啱寫完嗰段故事，邊個角色名出現過就當佢活躍（生圖功能已經咁做）零成本 · 已驗證 · 唔使 GM慢一個回合（睇上一段）· 中文單字名易漏
回合整理員（現有）每回合之後本身已經有個 AI 整理「今回合邊個出場」（餵走馬燈名單嗰個）AI 判斷準 · 已經行緊 · 零額外成本一樣慢一個回合 · 要對返角色卡
開講之前掃一掃（新）講故事之前，先用平 AI 掃一掃邊個 NPC 要諗即時、唔慢回合= 變相起返個迷你 GM（正正係 light-core 想拆嘅嘢）· 又貴又慢
✅ 我建議
用「回合整理員 + 認名」（兩個都係現成、零額外 AI 成本、唔使 GM）。代價係 NPC 嘅內心戲係反應上一回合啱啱發生嘅事 —— 但呢個其實好自然（人都係事後先有反應），唔似 bug。堅決唔好為咗即時而加返「開講前掃一掃」，因為嗰個就係 light-core 特登拆走嘅干預層，會令深模式又慢返、又貴返、又走返轉頭。

3玩家會見到啲咩

守住沉浸感原則 — 唔好變 dashboard / 唔好裸數字

NPC 內心戲

主要透過故事文字流露（角色語氣、行動體現佢心入面諗緊咩）。另外深模式可以有個可摺埋嘅「心聲」面板（撳開先睇到佢哋諗緊咩），似 ChatGPT 嗰個思考過程 —— opt-in 撳開、預設收埋、永遠唔會漏入正文。

擲骰 / 任務

擲骰結果融入敘事（「你險險⋯」），加一個輕量結果提示。任務／機制狀態用 AI 自己揀嘅自適應面板（質性顯示，唔係裸好感度數字條）。現有嗰啲裸數字條會喺呢步一齊換走。

紅線 內心戲永遠唔可以原文漏入正文（啱啱先修完一整類「後台嘢漏入故事」嘅問題）· 任何顯示都係 opt-in 撳開 · 唔做列表式 journal / dashboard。

4成本同收費

點解深模式一定要 opt-in / 收多啲
模式每回合 AI 工作量速度每回合額外成本
輕模式（預設）1 個 AI（講故事）最快—
深模式1 個講故事 + 最多 3 個 NPC 各自諗（並行）+ 擲骰／任務慢少少~18 分／回合（3 個 NPC × 6 分）

所以深模式天然係一個 opt-in 掣（似而家嘅「深度思考」掣），開咗收多啲分。3 個 NPC 並行 ≈ 多 1.8 秒（唔係逐個排隊嘅 5.4 秒）。失敗嘅 NPC 唔收費（hard rule #4）。

硬規矩 成人故事嘅 NPC／機制 AI 一定要行 Grok（CrazyRouter），永不行 Claude／Haiku（hard rule #5：成人流量上 Anthropic 會封成個平台）。呢條路由現有 pickUtilityModel 已經做緊，直接重用。

5分階段落地

由細到大、每步都自己 work · 唔好一鑊過
1

NPC 內心戲（撈返舊碼 + 接新掣）~1 session

由 git 撈返舊 NPC agent 碼（機器本身好地地）→ 接「回合整理員 + 認名」做新觸發 → 接返記憶 + 心聲面板 + 收費。呢步完 = agent mode 真係 work。

2

擲骰 / 機制（畀講故事 AI 識自己叫機制）~1–2 session

創作時順手生成「呢個故事有咩機制」→ 講故事嗰個 AI 識自己叫擲骰／機制 → 後台計結果 → 照結果寫。擲骰回歸做機制之一（唔係全域開關）。

3

任務系統（最大、要由零設計）~1–2 session

定義任務嘅資料結構（目標／狀態／完成條件）+ 講故事 AI 點開／推進／完成任務 + 自適應面板顯示進度。文檔暫時只當佢係一個「面板」，真正嘅任務邏輯要新設計。

建議次序 先做 階段 1（NPC 內心戲） —— 最快、最大差異化賣點、撈返舊碼。行得通、你玩過滿意，先逐步加 C1 → C2。每階段都係一個可以即刻 demo 嘅完整功能。
