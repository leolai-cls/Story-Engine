01我哋做緊咩

一個互動式故事網頁平台，AI 做敘事者，用戶做主角。三個入口、同一個引擎。

三個入口

用戶可以由三個途徑開始一段故事體驗：

自己創作
用戶寫一個 prompt（例如「我想玩一個 1980 年代香港古惑仔故事，做新仔入會」），AI 即場幫你建立故事世界、角色介面同開場。
社群分享
玩其他用戶創作並公開嘅故事。Library 入面有評分、tag、語言、分類。你玩嘅進度同原作者完全隔離。
官方精品
由我哋同邀請作者精心設計嘅 premium 故事。質素同細節高過一般 UGC，做平台招牌。
為咩一個引擎可以做晒三件事
三個入口背後，「故事」嘅本質係一樣 —— 一個 prompt 種子 + 一套狀態介面 + AI 持續敘事。分別只係邊個寫個 prompt（用戶/社群/官方）。所以我哋唔需要建立三個產品，建立一個強嘅引擎就夠。

02市場機會

市場已經有 AI Dungeon、Character.AI 等玩家，但中文圈基本上冇人服務，而且全球玩家都有3個未解決嘅痛點。

三個未解決嘅大痛點

1
AI 記性差
100 回合後 AI 完全唔記得你係邊個。係用戶離開嘅 #1 原因。
2
冇 RPG 感
純文字對話，冇角色狀態、冇成長、冇收藏品。玩落似 chat 多過 game。
3
介面千篇一律
無論你玩龍與地下城定戀愛劇情，介面都係一樣，完全冇代入感。

我哋三個差異化

🌏
中文圈 first
繁中體驗、HKD/TWD 訂價、本地文化故事。市場藍海。
🧠
真正記得你
四層記憶架構（後面解釋），AI 永遠記得發生過咩。
🎨
介面跟故事變
玩咩故事就有咩介面 — D&D、戀愛、體育、偵探 …… 全自動。

03核心創新 — 故事自適應介面

呢個係我哋最有 wow factor 嘅產品特色，亦都係其他平台冇得抄嘅護城河。

佢點 work

1
用戶寫故事概念。例如：「我想玩一個 NBA 後衛新秀嘅故事，目標係攞 MVP」。
2
AI 設計專屬介面。AI 讀你嘅 prompt，自動決定呢個故事需要展示乜嘢狀態 — 例如體力、得分、籃板、助攻、隊內位置。
3
用戶確認 / 微調。可以加減欄位、改名、調範圍。然後 AI 寫好開場，正式開始玩。
4
跟住情節即時更新。你打場 30 分，得分數即時加；你受傷，體力即時跌。介面同故事永遠同步。

唔同故事 → 唔同介面（真實例子）

點解呢個係護城河
市面上所有 AI 故事 app 都係硬寫死「呢個介面就係咁」。要做我哋呢種「介面跟故事變」，需要：(1) AI 識生成 schema、(2) 前端有 generic renderer、(3) 後端有狀態 sync。三樣都唔難，但夾埋係新東西。我哋做出嚟，後來者要追要 6-12 個月。

04長期記憶系統

AI 故事最大嘅幻覺：「個 AI 記得我」。實際上佢淨係記得最近 20 條 message。我哋用四層架構解決呢個問題。

1
短期記憶 — 最近 20 回合
完整原文放入 context。確保即時對話自然流暢。
2
中期記憶 — 滾動摘要
每 20 回合自動摘要成一段，永久保存。背景任務做，唔影響玩家速度。
3
長期記憶 — 語意檢索 (RAG)
每回合都儲存成「向量」。每次新行動，AI 自動找返過去最相關嘅情節塞入 context。所以你提起 50 回合前嘅事，AI 都搵得返。
4
角色檔案 — 自動 Lorebook
AI 自動由故事入面抽取角色、地點、物品建立檔案。一旦 mentioned 邊個 NPC，相關背景自動注入。
用戶實際體驗
玩家試咗 80 回合，跟一個 NPC 結咗婚，然後消失 10 回合做其他嘢，再返嚟。其他平台嘅 AI 會問「你係邊位？」。我哋嘅 AI 會講「你太太剛才打你電話問你今晚返唔返屋企食飯」。呢種感覺 = 留客。

04.5故事完整性引擎（Narrative Integrity）

解決行業 #2 churn 原因 ——「取悅型 AI / Yes-Man Problem」。AI 不斷迎合玩家，NPC 冇靈魂，玩家想做乜就做乜，30 分鐘 boring quit。

3 個業界未解問題

A
故事走偏
AI 唔斷取悅玩家，故事失去主題同 stakes
B
NPC 冇靈魂
玩家叫 NPC 做咩就做咩，性格隨意被打破
C
玩家暴走
想做乜就做乜，冇能力限制，冇後果，冇代入感

4 層解決架構

1
故事聖經（Story Bible）— 不變嘅骨架
創作時 AI 生成：核心衝突、世界規則、故事弧 (3-5 個 Act)、語調風格。每 turn 注入 context，玩家行動唔可以推翻。鎖定 Anthropic prompt cache，幾乎 0 額外成本。
2
角色卡（Character Cards）— NPC 嘅靈魂
每個 NPC 有：性格、過去、目標、紅線（red lines）、講嘢風格、發展弧。紅線觸發即 in-fiction 拒絕。NPC 真正獨立。
3
能力檢定（Skill Check）— 真正嘅 RPG 感
玩家做高風險行動 → 系統擲骰 (skill + d20 vs 難度)。失敗有真實永久後果（HP、好感度、聲譽 …）。唔可以 reset 同一 turn。UI 有擲骰動畫。
4
Director Model — 背景仲裁 AI
每 turn 第一次 LLM call（用平價 Model 如 Haiku），審核玩家行動：違反聖經？踩 NPC 紅線？需要 Skill Check？Arc 走偏？輸出 verdict 俾 Narrator。+20-30% credits/turn 但係質素飛躍。

真實對比 — 戀愛故事第 5 回合

玩家見咗林思雅 2 次（好感度 30%），輸入：「我親林思雅然後求婚」

🚫 業界做法（AI Dungeon / Character.AI）

「林思雅紅住面接受你嘅吻，細聲講：『我願意…』」

→ Yes-man AI，5 turn 贏咗遊戲，冇 stakes，30 分鐘 boring quit

✅ Story Engine 做法

Director Verdict：違反林思雅紅線（快速進展）+ 違反 Story Arc（Act 1 認識階段）+ 需 Skill Check：口才 2/10 vs 難度 19 → 失敗

「林思雅整個人僵住，狠狠推開你。你見到佢眼眶紅咗，但唔係感動 — 係受傷。

『你…你以為我係咩？』佢聲音震，『我屋企已經有人想將我嫁出去當交易品。我以為你唔同。』

佢轉身走，留低你企喺奶茶店門口。經過嘅同學望住你，有人細聲講：『仲以為佢係 nice guy…』」

狀態更新：林思雅 30% → 0% · 校園聲譽 -15 · 永久記錄呢一刻，未來所有對話都會 retrieve 呢個 memory

點解呢個係 MVP day 1 hard requirement
如果第一個試玩 Story Engine 嘅人都覺得 AI 喺度討好佢，我哋連 launch 嘅資格都冇 — 因為呢個就係 AI Dungeon / Character.AI 已經輸咗嘅地方。Narrative Integrity 唔係 nice-to-have，係我哋同對手 differentiate 嘅核心。

避免框架過鬆 / 過緊 — Bible 3 層 calibration

呢個係 design tightrope：框架太弱 = yes-man AI；框架太強 = 寫死故事，殺死 emergence。解決方法 = Bible 分 3 層，Hard Locked 層要極少，emergence 嚟自層之間 interaction。

層字數預算例子（戀愛校園）點 enforce
🔒 Hard Locked 150-300 字
(5-10 條)		 「呢個故事關於認真感情」
「林思雅紅線：唔接受不忠」
「現實世界，冇魔法」		 System prompt + Director 強制
🎯 Soft Guided 300-500 字 故事弧 transition：用條件（「好感度 ≥ 60 AND 1-on-1 ≥ 3 次」）而唔係 turn number Director 引導但有彈性
🎨 Open 0 字 對白細節、場景、NPC 反應、subplot、世界細節 outside invariants 唔寫，Narrator 自由發揮
Emergence 嚟自層之間嘅 interaction
林思雅紅線 = 「唔接受不忠」(Hard Locked)。玩家偷食 → Bible 冇寫佢點反應（呢層 Open）。Director 只 enforce 後果一定要有，但點樣有後果完全由 Narrator emergence。可能 1：佢喊住 block 你電話。可能 2：佢冷靜離開。可能 3：佢計復仇，將你嘅事告訴另一個女角，連帶 -20% 好感度。每個 playthrough 結果都唔同。

3 層 API 防禦 — 點樣 enforce Bible 唔被玩家 prompt 推翻

你嘅 intuition 完全 correct ——「每次 API call，Bible 優先級高過玩家 prompt」係 LLM API 嘅實際運作方式。我哋疊 3 層：

1
System Prompt Priority
Bible 放 system role，玩家 prompt 放 user role。LLM 經 RLHF 訓練成 system 優先級 > user。95%+ 普通玩家 prompt 攔到。
2
Director Model 仲裁
Narrator 寫之前，cheap LLM 預先審核玩家行動。攔截老練玩家嘅 jailbreak 嘗試。
3
Tool Calling Structured Output
state_delta 必須符合 JSON Schema。AI 唔可以 hallucinate 或被 prompt 騙到輸出唔合理 state（e.g., 玩家叫「我升 100 級」，AI 都唔可以擅自加 100 級）。
Prompt Caching = Bible 可以寫得 detailed 而唔貴
Claude / OpenAI / Gemini 全部支援 prompt caching。Bible + Character Cards 嘅 system prompt 前綴可以 cache，input cost 平 90%。即係：每個 NPC 可以有 200 字 backstory + 5 條紅線，每 turn 注入，cost 仍然好低。

06成人模式（Adult Mode）

預設關閉。要開啟必須完成年齡驗證。開啟後系統會自動隔離流量，避免大公司 ban 我哋個 account。

1
用戶想開啟成人模式 → 必須先做 Stripe Identity 年齡驗證（KYC，提交身份證自拍）。
2
驗證通過後，profile 解鎖「成人模式開關」，用戶自己揀開唔開。
3
開啟咗成人模式之後，AI Model selector 只會顯示容許成人內容嘅 Model（Open Source via OpenRouter）。Claude / OpenAI 自動隱藏。
4
內容過濾系統會跳過一般 NSFW 過濾，但 永遠保留 CSAM / 違法內容嘅 pre-filter（呢個係法律底線，無論咩模式都要有）。
點解要咁設計
Anthropic、OpenAI 嘅 API TOS 寫到明：違反內容政策會 ban 你個 account。如果用戶喺 Claude 上面生 NSFW 內容俾人 report，整個平台所有用戶都 down。所以我哋強制：要 NSFW？只能用唔會 ban 我哋嘅 Model（Open Source via OpenRouter）。Defensive design。

07用戶體驗流程

三個關鍵 user journey：創作、遊玩、分享。

創作一個故事

1
用戶按「新建故事」，輸入概念（一句、幾句、定一段都得）。
2
AI 5-10 秒內生成：故事介面 schema + 開場敘事 + 建議封面 prompt。
3
用戶睇 preview，可以微調介面欄位（加減、改名、調範圍）。
4
確認 → 故事保存 → 自動開始第一次遊玩。

玩一個回合

1
玩家輸入行動（例：「我送花俾林思雅」）。
2
AI 串流出敘事（一個字一個字打出嚟，有打字機效果）。
3
敘事完，側邊介面即時更新（林思雅好感度 +12，零用錢 −150）。
4
Credits 扣除，自動儲存。背景任務更新記憶系統。

分享一個故事

1
創作者揀「公開分享」（或者「分享連結（只限知道 link 嘅人）」）。
2
故事入到 Library，可以被搜尋、評分、評論。
3
其他用戶點「玩呢個」，建立佢自己嘅進度。原作者嘅故事唔會被改動，每個玩家狀態獨立。

08開發路線圖

Solo + AI 輔助開發。每個階段都係可以單獨完成、單獨驗收嘅完整功能塊。

階段 0 — 地基
網站基礎、用戶登入、設計系統。一個用戶可以登入、見到 marketing landing page。
階段 1 — 故事引擎
創作 + 遊玩 + 故事自適應介面 + Story Bible + Character Cards 生成。一個用戶可以由零創作一個故事，玩到幾回合，介面真係跟住情節變，NPC 真係有人格。
階段 1.5 — 故事完整性
Director Model 仲裁 + Skill Check engine。玩家試突破劇情/角色，AI 會 in-fiction pushback 而唔係取悅。MVP day 1 hard requirement。
階段 2 — 長期記憶系統
四層記憶架構齊備。玩家可以玩 50+ 回合而 AI 仍然記得開頭發生嘅嘢，仲記得邊個 NPC 講過咩、做過咩。
階段 3 — 多 Model + Credits
用戶可以揀 AI Model。Credits 系統 + 每個 Model 計費。
階段 4 — 訂閱付費
Stripe 訂閱 + 自動續訂 + Credits 增值包。用戶可以付錢。
階段 5 — 社群
公開 Library + 搜尋 + 評分 + 評論。用戶可以分享同玩其他人嘅故事。
階段 6 — 成人模式
年齡驗證 + 內容分流 + OpenRouter 整合。Storyteller 級別以上可以開。
階段 7 — 上線打磨
5 條官方精品故事 + 新手引導 + 全方位優化 + 分析工具。準備公開發佈。

09每階段點驗收

每完成一個階段，行一次完整 flow 確認真係 work 至 move on。

  • 階段 1：創作「戀愛校園故事」 → AI 生成 schema（好感度 / 心情 / 零用錢）+ Story Bible（核心衝突 / 故事弧）+ 3 個 NPC 角色卡（包紅線）→ 玩 3 回合 → 介面真係跟住情節變
  • 階段 1.5：第 5 回合輸入「親林思雅同求婚」 → Director 拒絕（觸發紅線 + Arc 唔啱）+ 強制 Skill Check 失敗 → Narrator 寫 in-fiction pushback，好感度大跌
  • 階段 2：玩 30 回合之後問 AI 第 1 回合做過咩 → 答得啱。問林思雅最近一次唔開心係幾時 → 答得啱
  • 階段 3：由 Claude 切到 GPT-4o → 下一回合用 GPT，Credits 按比例扣
  • 階段 4：Stripe 測試模式落 $9.99 → Credits 即時入賬 5,000，下個月自動續訂
  • 階段 5：用戶 A 公開故事 → 用戶 B 玩到 → 兩個進度完全獨立
  • 階段 6：未驗證年齡嘗試開成人模式 → 被擋 → 完成 Stripe Identity → 解鎖 → Model selector 只顯示 OpenRouter
  • 上線前：50 個並發玩家壓力測試，平均回合響應時間 < 8 秒，Credits 賬目 100% 一致
