HIGH P0BW2-H-01 Fork passes UUID as language-detection context → Chinese stories route to Gemini Flash (58% cost bloat)

File: web/src/lib/community/actions.ts:471-472 (Wave 1 fix surface)

Bug: Wave 1 fix wired forkStoryToPlaythrough to call pickModelForTier(tierPref, params.storyId). params.storyId is a UUID (e.g. "3f8a1c2b-...") — 0% CJK ideographs. isChineseContent() at tier-router.ts:30-37 returns false. Standard tier therefore routes to gemini-3-5-flash instead of glm-5-1.

Cost impact (Standard-tier user forking a Chinese story · the canonical launch path):

Modelcredit_multiplierEst turn costΔ vs intended
glm-5-1 (intended)1.0~$0.024—
gemini-3-5-flash (actual)1.5~$0.038+58%

Comment at community/actions.ts:469-470 says "Standard-pool will lean to GLM-5.1 by default (CJK bias) which matches our 中文 launch market." — but the code does the opposite of what the comment claims because the proxy string is wrong.

Compounding factor: tier-router.ts:59 sets const isCjk = context ? isChineseContent(context) : true — i.e. missing context defaults to CJK (correct for our market). But UUID-shaped context reliably overrides that to false. Passing undefined instead of UUID would actually be correct.

Fix (one of):

Option A (minimal · 1 line): Pass undefined instead of UUID — falls back to CJK-default routing. Aligns with the comment.
resolvedModel = pickModelForTier(tierPref, undefined);

Option B (better signal): Read the story's title/description from DB and pass that as context — proper language detection per story.
Fork RPC already has the story row — extend it to return title or pre-fetch via SELECT title, description FROM stories WHERE id = $1.

Recommended: Option A for Wave 3 (cheap · safe default). Option B is BACKLOG (better signal but adds query · marginal benefit since CJK-default already correct for ≥80% of forks at launch).

Why Wave 1 missed it: Wave 1 (Security/Correctness) flagged "tier not wired in fork" as P0B-CRIT-02. The fix added the call but didn't audit the quality of the context arg passed. This is the same error class as Wave 1's findings — wire-up correctness ≠ semantic correctness.

MEDIUM · UX polish / cost

MED P0BW2-M-01 Creation form spinner hardcodes "sonnet-4.6 · 生成中…" — wrong for Standard tier users

File: web/src/app/[locale]/stories/new/creation-form.tsx:280

Generation progress UI displays sonnet-4.6 · 生成中… as the model label for all 4 parallel tasks. But createStoryFromPrompt (the action that backs this form) now resolves the user's tier via pickModelForTier(tierPref, seedText) — for Chinese prompts on Standard tier, the actual generation model is GLM-5.1, not Sonnet 4.6.

UX impact: a user on Standard tier creates a Chinese story, sees "sonnet-4.6 · 生成中…" — feels like premium model is being used (they didn't pay for it) OR feels like a bug (display vs reality drift). Either way, trust hit.

Also problematic for English prompts on Standard (routes to Gemini Flash · still shows Sonnet 4.6 label).

Fix: Read user's current tier server-side, compute the actual model label, pass to form via initial prop. Same dynamic-compute pattern already used by TierPicker for credit estimates.
MED P0BW2-M-02 TierPicker uses Tailwind colors · AdultModeToggle uses --se-* tokens · same Settings page · visual drift

Files: web/src/components/settings/tier-picker.tsx vs web/src/components/settings/adult-mode-toggle.tsx

TierPicker (Wave 1 surface) uses Tailwind utility classes for color: text-emerald-700 dark:text-emerald-300, bg-emerald-50, border-primary, bg-primary/5, etc. AdultModeToggle (its direct sibling on the Settings page) uses CSS variables: var(--se-surface), var(--se-danger), var(--se-border-strong), var(--se-shadow-modal).

This means on Settings page, two cards immediately adjacent (preferences + adult mode sections) render with different color systems. Per Session 9 the entire UI tier was ported to the Grok+Netflix --se-* token system (47 artboards). TierPicker is the only major card in Settings still on raw Tailwind.

The Tailwind colors don't outright clash but are off-system — slightly different saturation, hover state pattern, etc. A designer reviewing this page would spot it in 2 seconds.

Fix: Convert TierPicker's color literals to --se-* tokens. ~30 minute refactor. Defer to Wave 3 or independent UI-tier task.

LOW P0BW2-L-02 Adult mode re-enable doesn't auto-restore prior tier · acceptable but worth noting

Flow: user has default_tier='adult' → disables adult mode → Wave 1 fix resets default_tier='pro'. Later (post-KYC) user re-enables adult mode. They must manually re-pick "Adult" in TierPicker — no auto-restore to their prior preference.

Why this is fine: (a) the user just went through the adult-mode consent dialog, so they're already in "I'm setting up adult" mode and natural next step is pick the tier; (b) auto-restoring would require storing "previous tier" somewhere (extra column or local state); (c) the friction is one click.

Worth noting because some users may not realize they need to re-pick. Acceptable for MVP; revisit if support reports confusion.

Mitigation (optional): Toast on adult mode re-enable: "想用 Adult tier 嘅話請喺敘事 AI Tier 揀返"
LOW P0BW2-L-03 Dynamic import at server-action callsite adds ~5-20ms on first call · fork path acceptable

Wave 1 fix at community/actions.ts:471 uses await import("@/lib/ai/tier-router") rather than a top-level import. This is presumably for circular-import avoidance (the same pattern is used at credits.ts:496 for MODELS). On first call per lambda instance, Node bundles & loads the module — measured at ~5-20ms warm-cache miss. Subsequent calls within the same lambda are zero-cost (module cached).

For forkStoryToPlaythrough, this is fine — fork is a rare action (once per playthrough), not in any per-turn hot loop. The ~10ms is well under perceptible latency for a redirect-to-play action that already takes hundreds of ms (RPC + DB writes).

Confirmed via grep — tier-router is also imported at top-level in stories/new/actions.ts:12 with no circular issues. The dynamic import in fork is a stylistic choice; could be promoted to top-level for consistency, but not required. Concern dismissed.
