web/src/lib/billing/credits.ts:498-528 · web/src/lib/billing/credits.ts:78-156 (MODEL_PRICING)
Attack:
  1. Malicious user calls Server Action forkStoryToPlaythrough({ storyId, llmModel: "text-embedding-3-small" }) (any free-tier authenticated user · the Server Action endpoint accepts arbitrary JSON · no input validation on params.llmModel).
  2. Fork RPC fork_story_to_playthrough(p_llm_model: "text-embedding-3-small", ...) creates playthrough with llm_model = "text-embedding-3-small". RPC has no CHECK constraint · no narrator-only validation · no trigger.
  3. On turn POST: userTierAllowsModel checks MODELS["text-embedding-3-small"] → undefined → falls through to modelId in MODEL_PRICING → TRUE (entry exists at credits.ts:98-101 for legit embed_charge use). Returns {allowed: true, reason: "legacy_model"} · console.warn fires only in non-prod.
  4. Turn handler proceeds. estimateTurnCredits("text-embedding-3-small") → input $0.02/1M + output $0/1M → ~0 credits estimate → pre-balance check trivially passes.
  5. getProviderModel("text-embedding-3-small") at providers.ts:49 → getModel throws → catch → falls back to claude-sonnet-4-6. Actual narration uses Sonnet.
  6. Post-stream computeTurnCredits at route.ts:920 uses narrator.modelId = pt.llm_model = "text-embedding-3-small" → charges at embedding rate. Sonnet narration (~$0.060/turn = 120 credits) gets billed as ~$0.0001 (negligible) = essentially free turns.
Impact: ~99% undercharge per turn. Same severity class as Wave 1's original "permissive bypass". Cost leak scales with user activity. Founder Adventurer tier ($9.99/mo · ~250 turns) becomes free at scale. Hard rule #4 violation (credit ledger trust).

P0AW3-LOW-01 MODEL_PRICING typed as Record · not as const · runtime mutable LOW
web/src/lib/billing/credits.ts:78
export const MODEL_PRICING: Record<string, ModelPricing> = { ... }. The const keyword only prevents reassignment of the binding · object mutations (MODEL_PRICING['fake-model'] = {...}) are NOT prevented at runtime · only at TypeScript compile time (and even then, Record is wide-open · would need as const or explicit literal type for compile-time freeze). Exploitable only via code-side compromise (some other vuln writes to the export) · not user input. Low severity for now.
Fix: const MODEL_PRICING = Object.freeze({ ... } as const) · or define narrator allowlist separately as Object.freeze(new Set([...])). Defensive only.
P0AW3-LOW-02 in operator traverses prototype chain · theoretical pollution vector LOW
web/src/lib/billing/credits.ts:518
JavaScript x in obj returns true for inherited properties · including anything on Object.prototype. If an upstream prototype-pollution vulnerability lands a key like "foo" on Object.prototype, "foo" in MODEL_PRICING returns true. No known pollution vector in current dependencies · Node.js requires explicit polluting code path · theoretical only.
Fix: Use Object.prototype.hasOwnProperty.call(MODEL_PRICING, modelId) or move to a Set.has() based allowlist (which doesn't have prototype semantics). Aligns with the CRIT-01 fix (explicit narrator Set replaces the pricing-table lookup entirely).
