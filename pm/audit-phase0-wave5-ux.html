P0W5-UX-L-02 · Migration 0022 trigger error message not localized; only browser-console attack path
LOW · ACCEPT

If a user (or buggy code) directly writes playthroughs.llm_model, the trigger raises: "llm_model is locked at playthrough creation · cannot be changed mid-game (hard rule #15 corollary)". This is an English Postgres error that would surface as a Supabase 500 in the client.

Why acceptable:

  • No app-code path writes llm_model post-create. The only existing playthroughs.update call (turn route line 894) updates current_state / turn_count / last_played_at only.
  • The trigger exists specifically to block browser-console / SQL-injection paths — i.e. the attacker. The attacker doesn't need a friendly 繁中 error.
  • If a future legitimate code path ever needs to swap llm_model, it would do so via service_role (Stripe webhook · admin tool) which bypasses the trigger.

Fix: none required. Accept as documented limitation. If desired, add to BACKLOG: "Trap trigger error in Supabase response handler if a future feature exposes model-switching."
