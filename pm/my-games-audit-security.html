MG-SEC-MED-01 SiteHeader auth.getUser() x 每個 page render · 3-call duplication Med
web/src/components/site-header.tsx:23-26 · web/src/lib/supabase/server.ts:4
SiteHeader 而家係 async server component · 每次 render 都 call supabase.auth.getUser()。問題：
  1. middleware (updateSession) 已經 call 過一次 (lib/supabase/middleware.ts:32)
  2. 多個 page (/my, /library, /settings, /play/[id]) 自己再 call 一次做 auth gate
  3. SiteHeader 再 call 第 3 次
因為每個 createClient() 開新 supabase instance · @supabase/ssr 嘅 per-instance getUser cache 唔會 share 跨 createClient call。getUser() 係 Supabase Auth API call（驗 JWT signature） · 唔係 cookie read。Hot pages 每 request 多咗 50-100ms。
Fix: 抽 user fetch 入 React.cache() wrapped helper · 或者 SiteHeader 改成接受 user prop 從 layout 傳入。Simpler short term：layout-level cache wrapper： 
// lib/auth/current-user.ts
import { cache } from "react";
import { createClient } from "@/lib/supabase/server";

export const getCurrentUser = cache(async () => {
  const supabase = await createClient();
  const { data: { user } } = await supabase.auth.getUser();
  return user;
});
SiteHeader + pages 都 import getCurrentUser() · React cache de-dupes within request。
