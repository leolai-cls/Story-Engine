MG-PERF-HIGH-01HIGHPERFORMANCECOST

SiteHeader 雙重 auth call — 每個 authed page render 多一次 getUser()

Where web/src/components/site-header.tsx:23-26 vs already-existing getUser() calls in: library/page.tsx:108 · library/[storyId]/page.tsx:46 · my/page.tsx:46 · settings/page.tsx:44 · stories/new/page.tsx:19 · profile/page.tsx
問題

SiteHeader 改寫成 async server component 之後喺 render 時 call supabase.auth.getUser()。但係 每個包含 SiteHeader 嘅 authed page 已經自己 call 過一次 getUser()（用嚟 redirect / RLS scope / adult_mode check）。 Grep 出 7 個 page 都有 self-call，全部都會行 SiteHeader → 即係 100% pages 都 double-RTT。

// SiteHeader (NEW)
const { data: { user } } = await supabase.auth.getUser();

// library/page.tsx — already does this at line 108 too
const { data: { user } } = await supabase.auth.getUser();

// my/page.tsx — already does this at line 46 too
const { data: { user } } = await supabase.auth.getUser();

Per-call cost: cookie read (~5ms) + JWT decode + Supabase Auth API call to refresh / validate (~30-80ms cold, ~10ms warm via Supabase server-side cache). On Vercel edge cold start: ~60-100ms 加倍。On warm hot path: ~15-30ms 加倍。Library 係最 trafficked page，呢個係 絕對的 regression on platform centerpiece。

實測影響：library page TTFB +30~80ms cold / +15~25ms warm；my page +30~80ms cold；settings/play/profile 全部受影響。Library 係 100% PMF discovery page — 即係 founder 講過嘅 "performance budget" 規則直接違反 (hard rule 17)。沒有 cache 抵消。
Fix 選項 A (推薦)：將 user 由 page 經 React Context / prop / cache(...) wrap 傳俾 SiteHeader。Next.js 15 嘅 import { cache } from "react" 可以 memoize per-request，咁兩處 call 第二次就 dedupe 為 cached value。
Fix 選項 B：建立 getAuthUser() helper 用 cache() wrap → 兩處 call 同一個 helper → React 自動 dedupe。約 5-line file。
緊急 ship 路徑：將 SiteHeader 改返 sync component，user 由 page 傳入做 prop，呢個係最直接 zero-risk fix。
MG-PERF-HIGH-02HIGHPERFORMANCE

Play page sequential count query — 每 turn / 每 refresh 多 50-80ms latency

Where web/src/app/[locale]/play/[playthroughId]/page.tsx:70-80 (Promise.all 缺 count) → 103-106 (sequential count)
問題

Total playthrough count query 喺 Promise.all batch 之 外，即係 sequential 行：

const [{ data: characters }, ...] = await Promise.all([
  supabase.from("story_characters")...,        // ~30ms
  supabase.from("playthrough_character_states")..., // ~30ms
  getMyPlaythroughs(supabase, ...),            // ~50ms
]);
// ↓ WAITS for above to finish, THEN starts
const { count: totalPlaythroughCount } = await supabase
  .from("playthroughs")
  .select("id", { count: "exact", head: true })
  .eq("user_id", user.id);  // ~50-80ms (exact count on potentially large table)

Play page render 喺 每次 turn 完成後 server re-fetch（client 用 refreshState → page-level navigate 唔會、但 user manually refresh、deep link 入嚟、share link、tab restore — 都會 trigger 完整 page render）。Founder 主場景。Every turn 都對 SELECT count(*) exact 行一次。

Cost: 50-80ms extra per page render. Cost: exact count 喺 100+ playthrough 用戶身上會 table-scan-ish (head:true 唔 fetch row，仲 OK，但 RLS predicate + count 唔 free). 重要 user-facing wait。
將 count query 拉入 Promise.all： 
const [{ data: characters }, { data: charStates }, recentPlaythroughs, { count: totalPlaythroughCount }] = await Promise.all([
  supabase.from("story_characters").select(...),
  supabase.from("playthrough_character_states").select(...),
  getMyPlaythroughs(supabase, { userId: user.id, limit: 12 }),
  supabase.from("playthroughs").select("id", { count: "exact", head: true }).eq("user_id", user.id),
]);
Zero-risk 1-line refactor，省 50-80ms。或者更好：將 count 改 sidebar 嘅 client-side responsibility — 用 SWR fetch on mount，page render path 唔需要等。

Hard-coded /${locale}/my 在 PlaythroughSidebar.tsx:150, 165, 203, 232 — 全部依賴 prop locale 正確嚮 in，並無經 i18n routing helpers verify。如果 user 個 cookie locale 同 URL prefix divergence（次站之內語言 switch、localStorage stale），sidebar nav 會帶錯 locale。

同樣 bug 喺 my/page.tsx EmptyState：

// my/page.tsx line 309 — 用 i18n Link 但又寫死 locale prefix
import { Link } from "@/i18n/navigation";
<Link href={`/${locale}/library` as never}> // ❌ DOUBLE PREFIX RISK

Sidebar：改 import path → import { Link } from "@/i18n/navigation";，再將所有 href 從 /${locale}/path 改 /path as never。
/my page：line 309, 317 改 href="/library" 同 href="/stories/new"，依賴 i18n Link auto-prefix。Line 92, 98, 105, 113, 181 都係同類問題（雖然 i18n Link 接受 hardcoded locale 但 best practice 應該唔寫死）。

/my page limit: 500 + client-side recount — power user 收 megabyte payload

Where web/src/app/[locale]/my/page.tsx:53-63
問題

page.tsx 行：

const all = await getMyPlaythroughs(supabase, { userId: user.id, limit: 500 });
const counts = { all: all.length, active: ..., archived: ..., abandoned: ... };
const filtered = tab === "all" ? all : all.filter(...);

每次 /my page render 都 fetch 全部 500 row + story join (title + genre + cover_image_url)。對 100 row power user：~500 row × ~250B JSON = ~125KB / request × MAU × visits/month。Heavy。Story join 抽 cover_image_url 但 list view 唔用（PlaythroughRow 用 Cover component 但 Cover 自己 generate placeholder hue from storyId — cover_image_url 唔讀）。即 cover_image_url 行 zero use 但每 row 攜帶。

Solo dev cost ceiling concern (CLAUDE.md hard rule 20 — Phase 2 memory已經食 ~46% COGS for adventurer plan)。額外 DB read + bandwidth 對重型用戶 = real money / month。
  1. 新增 RPC get_my_playthroughs_with_counts(user_id, status, limit, offset) — server-side filter + count returns。
  2. Counts 改用一次 SELECT status, count(*) FROM playthroughs WHERE user_id = $1 GROUP BY status RPC — 4 row 返。
  3. List 改 paginate (limit 50, page=N)，server-side filter by status。
  4. getMyPlaythroughs 拎走 cover_image_url（list view 唔用，~30B saved / row × 500 row = 15KB）。

MG-A11Y-MED-04MEDA11YUX

Mobile drawer 無 ESC dismiss / focus trap / body scroll lock / keyboard handling

Where web/src/components/se/PlaythroughSidebar.tsx:71-100 (mobile drawer block)
問題

Mobile drawer dismiss 只有 backdrop click。Drawer 開時：

  1. 無 ESC key handler — 鍵盤用戶撳 ESC 唔關
  2. 無 body scroll lock — 背後 narrative list 可以滾動 (mobile Safari / Chrome 視 drawer 為 overlay 不 prevent scroll)

A11y compliance：WCAG 2.4.3 focus order + 2.1.2 no keyboard trap exit。Real-life user pain low-medium (drawer 用咩唔多)。但 launch market HK + TW 有相當部分 a11y-sensitive group。
改用 Radix Dialog (shadcn) — automatic ESC, focus trap, scroll lock, ARIA states 解決全部 4 個 issue. ~10 line refactor.
OR 手寫 fixes：useEffect for ESC keydown + document.body 'overflow:hidden' lock + tabindex 管理.
