Phase 0.9 · 開工前 setup

5 個步驟搞掂後台

跟住做晒呢 5 步，Story Engine 就 connect 到真實 backend，可以開始 sign up、見到 data 流通。預計 15-20 分鐘。

⚠️ 重要：要起一個新 Supabase project
你而家 Claude MCP 連住嘅 Supabase project 已經有其他 app 嘅 data（似係 CLS Studio 嘅東西）。我哋嘅 migration 絕對唔可以套用過去，會搞亂 production data。

所以 Step 1 = 起一個 全新嘅 Supabase project 俾 Story Engine 用，獨立隔離。
1
起新 Supabase project
~5 分鐘 Required
  1. 登入 supabase.com/dashboard
  2. 右上角按 "New project"
  3. 填資料：
    Name: story-engine
    Database password: 強密碼，記低！
    Region: Southeast Asia (Singapore) ← 最近 HK/TW，latency 最低
    Pricing plan: Free ← MVP 階段免費 OK
  4. 按 "Create new project"，等 2-3 分鐘 provision 完
2
攞 API URL + anon key
~2 分鐘 Required
  1. 新 project dashboard → 左下角 Settings → API
  2. 會見到兩個 key：
    Project URL: https://xxx.supabase.co
    anon public: eyJhbGciOi... ← 安全，可以 expose 俾 browser
    service_role: eyJhbGciOi... ← 絕密！ 只可 server 用
  3. Copy 呢兩個 value（Project URL + anon public）
3
建立 web/.env.local
~2 分鐘 Required
  1. 喺 C:\Users\user\Desktop\text based RPG\web\ 入面起一個檔叫 .env.local
  2. Paste 落去：
NEXT_PUBLIC_SUPABASE_URL=https://你嘅-project.supabase.co
NEXT_PUBLIC_SUPABASE_ANON_KEY=你嘅-anon-key
NEXT_PUBLIC_SITE_URL=http://localhost:3000
💡 提示：呢個 file .gitignore 已經會自動忽略，唔會 commit 上 git。安全。

或者你可以直接話我知個兩個 value，我幫你寫入個 file。

4
跑 migration（建表）
~3 分鐘 Required

有兩個方法。揀一個：

方法 A（最簡單）：用 Supabase SQL Editor
  1. 新 project dashboard → 左邊 SQL Editor
  2. 按 "New query"
  3. 打開檔案 supabase/migrations/0001_initial.sql
  4. Copy 入面所有 SQL，paste 入 SQL Editor
  5. 按右下角 "Run"，應該見到 "Success. No rows returned"
  6. 左邊 Table Editor verify 見到 6 個 tables: profiles / stories / story_characters / playthroughs / playthrough_character_states / turns
方法 B：MCP 自動 apply（需要切換 MCP 配置）
  1. 你需要 update Claude MCP 配置，指向新 project
  2. 之後話我知，我可以用 mcp__supabase__apply_migration 直接 apply
  3. 呢個方法 future-proof — 之後 Phase 1/2 嘅 migration 都可以 MCP 自動做
5
啟用 Google OAuth（可選）
~5 分鐘 Optional

暫時 magic link email 已經夠用。想加 Google login 嘅話：

  1. Supabase dashboard → Authentication → Providers
  2. 揀 Google → Enable
  3. 需要 Google Cloud Console 攞 OAuth credentials（指南：Supabase docs）

呢步可以後尾再做。Phase 0.6 wire up 嘅時候 email magic link 已經 work。

6
GitHub + Vercel deploy
~10 分鐘 Phase 0.10

留到 Phase 0.9 完成 + Phase 0.6 wire up 之後再做。需要：

  • GitHub repo — Vercel deploy 要連 GitHub
  • Vercel account — 連去 GitHub repo 自動 deploy
  • Env vars 喺 Vercel dashboard — 同 .env.local 一樣嘅 keys
  • Domain（optional） — 你想用 storyengine.app / storyengine.hk / etc.

呢個 Step 6 我可以後尾 dedicate 一個 setup guide 同你 walk through。

✅ 完成 Step 1-4 之後，你應該有：
  • 新嘅 Supabase project（story-engine）
  • web/.env.local 入面有 SUPABASE_URL + ANON_KEY
  • Supabase 新 project 入面有 6 個 tables（profiles / stories / story_characters / playthroughs / playthrough_character_states / turns）
  • RLS policies enabled on 所有 tables
  • auto-create profile trigger active
